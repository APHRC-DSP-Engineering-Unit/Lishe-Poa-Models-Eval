# LLM-judge results

This folder holds the results of the **LLM-as-a-judge evaluation**. It checks how accurately three AI models pulled information off food product labels, compared with what human reviewers typed (the ground truth).

| | |
|---|---|
| **Products compared** | 1,500. The ground truth has 1,501 IDs. `F406_1` is an empty split with no model record, so it is left out. `F406_2` is compared with the models' `F406`. |
| **Models graded** | GPT-6-Sol, Gemini 3.8 Flash, Claude Opus 5.5 |
| **Judge** | OpenAI `gpt-4o-mini` (temperature 0), for text fields only |
| **Inputs** | `data/ground_truth.json` plus one JSON file per model in `data/` |
| **Generated by** | `judge_eval.py` (full run: 2026-11-18 10:28) |

## How each field is graded

| Field type | Fields | Graded by |
|---|---|---|
| Text | Product name, brand, manufacturer, country of origin, package type, ingredients, other label info | **LLM judge.** The model names are hidden from the judge (shown as A, B, C) to avoid bias. Values that match exactly (ignoring case, spacing and punctuation) are marked correct in code without calling the judge. |
| Numbers and codes | Category, barcode, package size, package count, serving size, nutrition basis | **Exact check in code** |
| Nutrients | Every nutrient value (energy, protein, fat, sugars, sodium and so on: 80 nutrient keys in total) | **Exact check in code** |

**Marks**

| Mark | Meaning |
|---|---|
| ✓ | Correct |
| ✗ | Wrong, missing, or invented |
| ~ | Partial. Allowed only for *ingredients* and *other label info* (long text where some items are missing). |
| blank | Empty in the ground truth **and** in every model, so it is not counted |
| ? | The judge call failed. Rerun the script to retry it. (None in the current run.) |

**Accuracy = ✓ ÷ (✓ + ~ + ✗).** Partial counts as not correct. A model **passes** an area when its accuracy is at least **85%**.

*Other label info* is correct if the model includes everything the humans typed. Extra text is allowed. It is not scored when the ground truth is blank.

## Files

| File | What it is |
|---|---|
| `extraction_judge_results.xlsx` | The main results workbook (sheets listed below) |
| `dashboard.html` | A standalone interactive dashboard. Double-click to open it. It is the same page as `site/llm-judge.html`, without the site navigation. |
| `dashboard/scorecard.json` | Accuracy per model, by area and by field (51 rows) |
| `dashboard/nutrients.json` | Accuracy per model, per nutrient (240 rows = 80 nutrients × 3 models) |
| `dashboard/products.json` | Correct ÷ checked per product, per model (4,500 rows = 1,500 × 3) |
| `judge_cache.jsonl` | Every answer the judge gave (1,477 products). **Don't delete it.** It is what lets reruns cost nothing. |
| `llm_judge_rows.json` | The per-product marks for the website. The overview and manual-review pages load it from `/data/llm_judge_rows.json` (served by `serve.py`). Written only by full runs of `judge_eval.py`, not `--limit` test runs. |

### `llm_judge_rows.json`

```jsonc
{"models": ["GPT-6-Sol", "Gemini 3.8 Flash", "Claude Opus 5.5"],
 "judge": "gpt-4o-mini", "when": "2026-11-18 10:28", "target": 0.85,
 "rows": {
   "J001": {
     "f": {"name": [["✗", "Incorrect product name."], ["✗", "…"], ["✓", ""]], …},  // per field: [mark, judge note] for each model, in "models" order
     "n": {"energy_kj": ["✓", "✓", "✓"], …},                                       // per nutrient: one mark for each model
     "v": [["✗", 19, 21], ["✗", 20, 21], ["✗", 20, 21]]                             // per model: [✓ only if every scored item is ✓, correct, scored]
   }, …}}
```

### Excel workbook sheets

| Sheet | Contents |
|---|---|
| **Basic analysis** | One row per product: ✓ if *every* field and nutrient of that product is correct for that model, ✗ otherwise. The total is at the bottom. |
| **Summary** | Leaderboard, a ✓/~/✗ count and accuracy for each field, *Models disagree* (products where one model is ✓ and another ✗), and notes |
| **One sheet per field** (Product name … Other label info) | Product ID, ground truth, each model's value, its mark and, for judged fields, the judge's note on why |
| **Nutrients** | One row per product × nutrient: ground truth, each model's value and its mark (about 13,400 rows) |
| **Comparison** | Everything side by side: one row per product, with a column group per field |

### JSON files (`dashboard/`)

Each file is `{"rows": [...], "meta": [...]}`. `meta` records the inputs, the judge model, the product count and the exporting script's source.

```jsonc
// scorecard.json: group is "Area" (Overall, Nutrient values, Codes and sizes, Text fields) or "Field"
{"group": "Field", "item": "Brand", "graded_by": "LLM judge", "model": "GPT-6-Sol",
 "correct": 1202, "checked": 1497, "accuracy_pct": 80.3}

// nutrients.json: products = how many products have this nutrient
{"nutrient": "energy_kj", "products": 753, "model": "GPT-6-Sol",
 "correct": 724, "checked": 750, "accuracy_pct": 96.5}

// products.json
{"product_id": "J001", "model": "GPT-6-Sol", "correct": 19, "checked": 21}
```

### Cache (`judge_cache.jsonl`)

There is one JSON object per line, one per product that needed the judge:

```json
{"key": "J004:e94c746d23ea",
 "result": {"model_A": {"package_type": ["✓", ""]},
            "model_B": {"package_type": ["✓", ""]},
            "model_C": {"package_type": ["✗", "Different packaging type: 'wrapper' vs 'pouch'"]}}}
```

`key` is the product ID plus a hash of exactly what was sent to the judge. `model_A/B/C` are the models in the order GPT-6-Sol, Gemini 3.8 Flash, Claude Opus 5.5. If a product's ground truth or a model's answer changes, its hash changes, and only that product is sent to the judge again.

## Headline results (current run)

| Rank | Model | Overall | Text fields | Nutrients | Products 100% correct |
|---|---|---|---|---|---|
| 1 | Gemini 3.8 Flash | 83.2% | 72.3% | 93.7% | 58 |
| 2 | Claude Opus 5.5 | 82.6% | 71.5% | 93.2% | 66 |
| 3 | GPT-6-Sol | 81.1% | 68.9% | 92.8% | 42 |

None of the models reaches the 85% target overall. All three pass on nutrients. For every model, the weakest fields are package count, other label info, product name, manufacturer and country of origin (all at or below about 58%). See the **Summary** sheet for the full breakdown.

## Regenerating

Run these from the project root:

```bash
.venv/bin/python judge_eval.py              # rebuilds everything here; uses the cache, so no new charges unless inputs changed
.venv/bin/python export_dashboard_data.py   # rebuilds dashboard/*.json from the cache (never calls the API)
```

`judge_eval.py` prints the estimated cost and asks before making any paid calls. If the cache already covers every product, it makes none.
